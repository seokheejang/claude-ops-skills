# best-practice — Output Reference

Quality Criteria 와 학습 저장 권유 기준.

> 출력 포맷 템플릿은 두지 않는다. 주제마다 필요한 섹션이 다르고, 고정 템플릿은 빈 칸을 채우게 만들어 오히려 내용을 희석시킨다. 아래 **Quality Criteria 를 만족하는 한** 구조는 주제에 맞게 짠다.

## 반드시 포함할 것

| 항목 | 이유 |
|------|------|
| **대안 비교** | 단일 선택지만 제시하면 리서치가 아니다. 대안이 명시되지 않았으면 직접 찾는다 |
| **합의 vs 논란 구분** | 업계가 합의한 부분과 의견이 갈리는 부분을 섞지 않는다 |
| **사용자 환경 적합성** | 일반론이 아니라 이 환경(규모, 클라우드, 블록체인 노드 운영)에서의 판단 |
| **출처 목록 + 검증 결과** | 각 출처에 `✅ 검증 OK` / `⚠️ 사유` / `❌ 사유` 표기 |
| **출처 다양성 평가** | 표면적 N개 vs 실질적 독립 1차 소스 M개 |
| **정보 기준일 + 도메인** | 시의성 기준이 무엇이었는지 드러낸다 |

## Quality Criteria

- **최소 출처 수**: 3개 이상 (가능하면 5개+)
- **출처 다양성 (표면적)**: 공식 문서 + 커뮤니티 + 블로그/사례 중 최소 2개 카테고리
- **출처 독립성 (실질적)**: 같은 1차 소스를 인용하는 출처는 1개로 카운트. 의견 갈리는 주제는 다른 입장 출처 1개 이상
- **시의성**: 도메인별 기준 적용 ([verification.md](verification.md))
- **Citation 검증**: 모든 출처 URL fetch + 인용 내용 확인 후 보고
- **AI 콘텐츠 식별**: 의심 신호 체크 ([sources.md](sources.md))
- **근거 없는 주장 금지**: 모든 주장에 출처 필수
- **불확실성 명시**: 확인 불가한 부분은 "확인 필요"로 표기

## 학습 저장 권유

리서치 결과가 **재참조 가치**를 가질 때만 끝에 한 줄로 권유한다. 매번 권유하면 의미가 흐려진다.

| 권유한다 | 권유하지 않는다 |
|---------|---------------|
| 명확한 결론 + 의사결정 근거 도출 | 단순 정보 조회 ("X가 무엇인가") |
| 비자명한 인사이트 (몰랐을 패턴/한계) | 결론이 모호하거나 ⚠️ 태그가 많음 |
| 향후 비슷한 결정에 재활용 가능 | 이미 알고 있을 자명한 내용 |

권유 문구는 `docs/learnings/<도메인>.md` 에 추가할지 묻는 한 줄이면 된다.
